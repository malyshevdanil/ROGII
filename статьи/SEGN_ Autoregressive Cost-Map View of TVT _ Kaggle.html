SEGN: Autoregressive Cost-Map View of TVT

Project Writeup · Jul 7, 2026

SEGN: Autoregressive Cost-Map View of TVT

Working Note -

Public LB: 6.1RSME
Team: Vishal Kishore

1. Problem Setup

  • The task is to predict TVT / stratigraphic depth for a horizontal well after the Prediction Start.

  • Inputs available:

    • Well path
    • Gamma-ray log
    • Vertical typewell

  • Our system is called SEGN - Structured Energy Geosteering Network.

  • SEGN does not directly regress TVT as a single number.

  • Instead, at every measured depth, it builds a cost map:

    • Candidate TVT values are scored.
    • Lower cost means the candidate is more likely.
    • The model then decodes a trajectory through the low-cost region.

Main idea

  • SEGN treats TVT prediction as a matching problem, not just a regression problem.

Mathematical View of SEGN

Concept Formula / Quantity Meaning
Candidate TVT grid z ∈ Z At every measured depth, SEGN considers many possible TVT candidates instead of predicting one value directly.
Cost map C_t(z) Cost assigned to candidate TVT z at depth step t. Lower cost means higher confidence.
Posterior over candidates p_t(z) = exp(-C_t(z)) / Σ_z' exp(-C_t(z')) Converts the cost map into a probability-like distribution over TVT candidates.
Mean decode z_hat_t = Σ_z p_t(z) * z Final prediction is the posterior mean. This reduced amplitude shrinkage compared to mode/soft decode.
Mode decode z_hat_t = argmin_z C_t(z) Picks the single cheapest candidate. This was brittle in self-similar GR sections.
RMSE RMSE = sqrt((1/N) * Σ_i (z_hat_i - z_i)^2) Main error metric used to compare approaches.
Anchor-relative offset Δ_t = z_t - z_anchor TVT is predicted relative to the last trusted anchor. Wrong anchors cause recursive drift.
Predicted offset Δ_hat_t = z_hat_t - z_anchor The model predicts movement away from the anchor rather than absolute TVT alone.
Gain correction z_corr_t = z_anchor + g * Δ_hat_t + b Captures the multiplicative under-scaling problem. Bias alone was not enough.
Bias-only correction z_corr_t = z_hat_t + b Tests whether the error is only an additive shift. This failed because the error was mostly gain/level related.
Affine diagnostic z_corr_t = α + β * z_hat_t + γ * h_t Used to test whether remaining error was mostly level, gain, or horizon drift.
Entropy H_t = -Σ_z p_t(z) * log(p_t(z)) Measures uncertainty of the cost-map distribution.
Valley sharpness sharpness_t ≈ 1 / H_t Sharp valley means confident evidence; diffuse valley means uncertainty.
Decode disagreement d_t = abs(z_hat_mean_t - z_hat_mode_t) Large disagreement flags ambiguous or self-similar sections.

Mathematically, SEGN can be viewed as learning a cost function (C_t(z)) over candidate TVT values rather than directly regressing TVT. The final prediction is decoded from the induced distribution (p_t(z)). This framing made it possible to separate three failure modes: bad evidence, bad decode, and anchor/gain drift.

  • The key diagnostic question throughout the campaign was:

Is the error coming from the evidence, or from how we read out the evidence?

2. How We Evaluated

  • Numbers are mostly leave-well-out CV RMSE of dTVT in feet.

  • Single-well results are treated as diagnostics, not final proof.

  • We tracked two validation signals:

    • Local CV
    • Public leaderboard slice, around 24% of test data

  • If a change helped CV but hurt the public slice, we treated it as likely overfitting our validation.

4. Why We Used an Autoregressive Framing

  • Many public-style approaches use:

    • Full-sequence DP / Viterbi
    • Beam search
    • Optimal transport-style alignment
    • Global warping of the log

  • These methods require knowing the right scale of the warp.

  • In this problem, that scale is not identifiable per well.

Key finding

  • Direction correlation between predicted and true movement was strong:

    • Around 0.93–0.97

  • But the required magnitude multiplier varied heavily:

    • From 1.05× to 6.55×

  • Local evidence could not reliably choose that multiplier.

Result

  • Full-sequence DP / Viterbi decode scored around 8.0 RMSE.
  • Chunked autoregressive trunk scored around 5.8 RMSE.
  • So we kept the autoregressive setup.

Tradeoff

  • Autoregression matches the real deployment protocol:

    • Only the prefix is known.
    • Future TVT must be predicted recursively.

  • But it introduces anchor drift:

    • A wrong anchor affects the next features.
    • This creates compounding error.

5. Cost-Map Evidence Fusion

  • SEGN builds a cost map over candidate TVT values.
  • The model does not guess TVT directly.
  • It searches for a low-cost valley that represents the likely stratigraphic path.

What worked

  • On well-supported sections:

    • The cost-map valley aligned with the true curve.
    • Decode was almost free.

  • On harder sections:

    • The model tracked the shape correctly.
    • But the whole valley was shifted by around 27–35 ft.

Main conclusion

  • The trunk had learned useful shape evidence.
  • The dominant failure was a level / calibration problem, not a shape problem.

6. Evidence Channel Audit

  • We audited the five fusion channels separately.

  • Two channels were clearly useful:

    • Bilinear channel: TCN × typewell interaction
    • Multi-head cosine matching channel

  • These produced sharper, better-localised valleys.

Weaker channels

  • Some auxiliary channels were:

    • Diffuse
    • Striped
    • Less localised

  • They still helped with coverage, but not with sharp localisation.

Lesson

  • Not every channel should be trusted equally.
  • Fusion should learn continuous trust instead of using hard rules.

7. Decode Experiments

Soft / mode decode

  • Soft or modal decode compressed the movement.
  • It undershot real peaks.
  • Diagnostic RMSE was 15.17.

Mean decode

  • Switching only the read-out to posterior mean improved the same trunk:

    • 15.17 → 11.36 RMSE

  • This was a large gain without changing the evidence.

DP decode

  • DP decode was rejected.

  • Problems:

    • Produced staircase-like trajectories.
    • Hard-committed to self-similar wrong evidence.
    • Scored around 6 ft worse than a flat anchor in a true-cutoff diagnostic.

Final choice

  • Mean decode was kept.
  • DP decode was banned, even if it sometimes looked locally attractive.

8. Anchor Drift and Fixes

Problem

  • Anchor-relative offset coordinates caused long-interval droop.

  • A previous_delta train/eval skew made recursive features inconsistent:

    • Training saw one kind of feature.
    • Inference produced another kind of feature.

  • Together, they created a feedback loop:

    • Wrong anchor
    • Wrong features
    • Worse next prediction
    • More drift

Diagnostic result

  • Same architecture, different anchor quality:
Start Condition RMSE
Oracle anchor at 0.90 cutoff 2.67–4.70
Real deployed 0.60 cutoff 7.01–13.57

Lesson

  • A lot of error was not because the evidence trunk was useless.
  • It came from recursive anchor drift.

9. K-Hypothesis Anchor Selection

Idea

  • Instead of carrying one anchor, carry K possible anchors.
  • Then train a selector to choose among them.

Why it was promising

  • Oracle selection among candidates scored 3.84 RMSE.
  • True single-anchor version scored 4.13 RMSE.
  • Baseline was 8.43 RMSE.

Interpretation

  • Multiple candidate anchors can hedge locally.
  • Surprisingly, oracle K-selection even beat the true single anchor.

Why it was not shipped

  • The real selector was better than chance.

  • But it hurt the actual submission.

  • Reason:

    • Training-time noise did not match real inference-time anchor errors.

Status

  • Mechanism is valid.
  • Not abandoned.
  • Parked until negative sampling / noise modelling is improved.

10. CRPS Loss Experiment

Goal

  • We tried CRPS to make the cost map more distributionally calibrated.

Result

  • It helped one local diagnostic.

  • But deployed score became worse:

    • 6.7 → 7.1

Why it failed

  • Fusion weights collapsed onto one channel.

  • Costmix channel weight increased:

    • 37% → 71%

  • Extra MLP channel decreased:

    • 21.4% → 5.2%

Lesson

  • CRPS rewarded apparent sharpness.
  • It reduced evidence diversity.
  • We rejected it.

11. Formation-Surface + XGBoost

Idea

  • Use geological tops and geometry directly.
  • Train a surface-style XGBoost model.

Result

  • Around 12 RMSE
  • SEGN was around 6.7 RMSE

Lesson

  • Surface regression alone was not enough.
  • It discarded the gamma-ray matching evidence.
  • Clean rejection.

12. External Ensemble Blend

Setup

  • Final blend used:

    • SEGN
    • sp45
    • fleongg

Result

  • Fitted optimum was around 0.38–0.40 SEGN weight.

  • Expected floor was around 6.51.

  • sp45 and fleongg were close to each other:

  • SEGN was the only genuinely decorrelated member.
  • Blend helped final score.
  • But it was mostly metric optimisation, not geological insight.

13. Main Data Insights

13.1 The biggest error is level / gain, not shape

  • Oracle affine correction on hard-well tail:

    • 6.24 → 2.44 RMSE

  • Bias-only correction:

    • 6.24 → 8.31 RMSE

  • So the error is not a simple additive bias.

  • It is mostly a multiplicative gain / level problem.

Important limitation

  • The required gain was not visible from test-time features.

  • Best available test-time feature correlation with required gain:

    • r = −0.107

  • This suggests a hard information limit, not just a missing model trick.

13.2 Prefix-fit regression showed systematic under-scaling

  • Predicted vs true offset:

    • Slope: 0.735
    • Bias: −0.34 ft
    • RMSE: 4.92
    • Correlation: 0.889

Interpretation

  • The model got direction mostly right.

  • But it systematically under-scaled movement.

  • Approximate correction implied:

    • Around 1.36× scaling needed.

13.3 Error is concentrated in hard sections

  • Easy sections near the anchor are close to solved.

  • Most remaining error occurs in:

    • Far sections
    • Diverging sections
    • Deep sections
    • Self-similar gamma-ray intervals

  • A single global correction does not solve this because the required correction is per-well.

13.4 Gamma-ray matching is weaker than it first appears

Diagnostic Result
GR–typewell NCC top-1 12.4%, about 15× random
GR–typewell NCC top-5 Falls to chance
GR–typewell W1 top-1 3.3%, about 4× random
Directional sign agreement 54.6% vs 50% chance

Lesson

  • Gamma-ray does contain signal.
  • But it is highly self-similar.
  • It can easily produce false matches.
  • This explains why hard DP-style commitment fails.

13.5 Public slice often disagreed with local CV

  • Some ideas improved local CV but hurt the board.

  • Examples:

    • CRPS
    • Some neighbour-leaning ideas

  • When CV and public slice disagreed, we trusted the public slice more.

Lesson

  • Local validation could be gamed.
  • A change had to survive both validation axes before being trusted.

13.6 Per-well routing should be learned, not hand-written

  • We did not use hand-written well buckets.

  • SEGN’s fusion gate learned continuous trust based on:

    • Valley sharpness
    • Matcher confidence
    • Distance past anchor
    • Local evidence quality

Lesson

  • Clean-log wells naturally leaned on matching channels.
  • Noisy wells leaned more on spatial / base priors.
  • Hard if/else routing made results worse.

14. Physical Interpretation

  • The cost map is physically meaningful:

    • It represents a distribution over stratigraphic position.
    • The decoded path should follow a coherent geological surface.

  • This is why DP decode was rejected:

    • It created staircase-like paths.
    • Those paths are not geologically plausible.

What was physically meaningful

  • Cost-map evidence fusion
  • Channel-level matching
  • Mean posterior decode
  • Anchor drift diagnostics

What was mostly metric optimisation

  • External blend with public artifacts
  • Some decode tweaks

Rule followed

  • Ship a change only if:

    • Physics suggested it, or
    • Both CV and public slice supported it

  • Avoid shipping changes based on one isolated local win.

Main conclusion

  • No single component carried the result.

  • Contributions came from:

    • Trunk localisation
    • Mean decode
    • Anchor drift fixes
    • Fusion calibration
    • External decorrelated blending

16. Model Uncertainty

SEGN has two native confidence signals.

16.1 Valley sharpness

  • Sharp valley:

    • Model is more confident.
    • Evidence is well-localised.

  • Diffuse valley:

    • Model is less confident.
    • Multiple TVT candidates look plausible.

16.2 Decode disagreement

  • We compare:

    • Posterior mean decode
    • Soft / mode decode

  • Large |mean − soft| indicates harder intervals.

  • This usually appears in:

    • Deep sections
    • Diverging sections
    • Self-similar-log regions

Important limitation

  • These signals show where the model is likely less accurate.
  • They do not reliably show where the model is systematically wrong.
  • The main remaining error, level / gain drift, is mostly invisible to these uncertainty signals.

CRPS note

  • CRPS was our attempt at true distributional calibration.
  • It failed because it collapsed channel diversity.
  • Therefore, we did not present calibrated intervals we could not defend.

17. Final Takeaways

  • The main progress came from diagnosing the failure mode precisely.

  • The key distinction was:

    • Evidence problem
    • Decode problem
    • Anchor drift problem
    • Level / gain calibration problem

  • Rejected ideas were still useful because they closed directions cleanly:

    • Global alignment
    • DP decode
    • CRPS
    • Surface XGBoost

  • The remaining open problem is gain / level calibration.

  • This problem now appears well-characterised rather than vague.
