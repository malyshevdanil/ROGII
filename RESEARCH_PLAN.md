# ROGII — долгосрочная research-программа (цель: пробить кластер 7.2 → 5.6)

Статус: публичный пайплайн ~7.5 (медальный кластер). Все быстрые твики проверены и
отклонены (см. ниже "Уже проверено"). Эта программа — систематический перебор
принципиально разных, более трудоёмких направлений. Каждый пункт проверяется
честно на held-out (pooled RMSE, GroupKFold по скважинам), результат фиксируется.

Документированный рычаг топов (из диагностики): **лучшее per-well сопоставление
GR ↔ typewell**. Tucker (rank 2, ~5) — только per-well данные. Значит рычаг в
качестве matching, не в данных.

## Направления к проверке (по приоритету)

### A. Лучший matcher (главный документированный рычаг) — ИСЧЕРПАНО, negative
Контекст: beam/DP-matchers сами по себе ~18 RMSE, что СЛАБЕЕ самого PF (~12). Их
микро-улучшения растворяются в пайплайне. Ни один вариант не приблизился к PF.
- [x] **A1. Полный DP (bidirectional).** beam=18.05, full DP=18.72 (чуть хуже),
      beam+DP блендинг=17.88 (крохи от декорреляции ~0.9%). Слабо. ОТКЛОНЕНО.
- [ ] **A2. Iterative EM-matching.** (не проверено; низкий приоритет после A1/A3)
- [x] **A3. Trajectory-informed transition.** КАТАСТРОФА: 69.8 (vs beam 18). Жёсткая
      привязка к наклону пятки запирает на неверном линейном тренде, не даёт следовать
      смене дипа (а это сигнал). Свобода ±2 в beam НУЖНА. ОТКЛОНЕНО.
- [ ] **A4. Pooled/master typewell.** (не проверено; требует кластеризации полей)
- Ранее в категории: NCC-в-PF (хуже), shape/derivative (value лучше 50% vs 24%),
  affine-калибровка beam (хуже). ВЫВОД: matcher лучше существующего через beam/DP
  построить не удалось. "Лучшее сопоставление" топов — структурно иное, невоспроизведено.

### B. Декоррелированные источники для ансамбля
- [ ] **B1. Свой sequence-aware GBM** (lag/lead фичи, не деревья-по-точкам) как 3-й
      декоррелированный движок в блендинг (диагностика: два публичных движка ρ≈0.89,
      нужен декоррелированный источник).
- [ ] **B2. Оптимизация весов блендинга** через честный GroupKFold (без утечки fleongg).

### C. Бимодальный хвост (40% ошибки; физически частично неустраним)
- [ ] **C1. Явное two-hypothesis tracking** — нести обе моды через PF, выдавать
      posterior mean (не post-hoc, а в динамике). Мы делали только post-hoc.
- [ ] **C2. Learned-детектор вероятности моды** на многих фичах (не один ratio; ratio
      слабый r=0.054, но комбо фичей может быть сильнее — риск переобучения высок).

### D. Робастная агрегация
- [ ] **D1. Per-well confidence → адаптивный откат к flat/линейному** когда матч
      неуверенный (уверенность из качества known-zone матча).

### E. Refinement обученной модели
- [ ] **E1. Учить остаток от ФИЗИКИ** (не от flat): true − physics_pred. Если у физики
      систематические per-position ошибки, коррелирующие с фичами — обучаемо. (Частично
      делает fleongg; проверить есть ли ещё структура.)

## Протокол
- Held-out: последние N скважин по ID (GroupKFold), pooled RMSE (метрика соревнования).
- Каждый эксперимент — парные сравнения на одинаковых сидах где возможно.
- Порог значимости: улучшение должно держаться на ≥60 скважинах (мы видели, как
  эффекты испаряются при увеличении выборки — deg-2 был шумом).
- Отрицательный результат = валидный результат, фиксируется.
