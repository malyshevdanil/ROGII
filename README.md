# ROGII — Wellbore Geology Prediction (Kaggle)

Рабочий репозиторий по соревнованию [ROGII - Wellbore Geology Prediction](https://www.kaggle.com/competitions/rogii-wellbore-geology-prediction).

---

## 🔑 Кратко (TL;DR)

Задача — предсказать `TVT` (положение горизонтального ствола в стратиграфической
колонке) для «слепого» хвоста каждой скважины по гамма-каротажу (`GR`), траектории
и эталонному разрезу (`typewell`). Метрика — **pooled RMSE в футах**.

**Результат:** лучший сабмит — **7.096** (public LB). На момент написания —
**85 место, зона серебряных медалей** 🥈.

**Как получили:** отталкивались от публичного production-пайплайна (particle filter +
beam search + GBM-стэкинг, ~7.23) и добавили **декоррелированный ансамбль частичных
фильтров** — это дало 7.230 → **7.096**, причём *ниже собственного шумового порога
пайплайна* (7.168), то есть это реальный выигрыш, а не везение с сидами.

**Главный вывод (и наша основная ценность):** большую часть работы мы потратили не на
гонку за цифрой, а на строгий ответ — **сколько остаточной ошибки вообще обучаемо?**
Ответ, подтверждённый ~9 независимыми способами и 7 нейросетевыми архитектурами:
**почти ничего.** Ошибка в eval-зоне — это дрейф, *направление* которого физически
отсутствует в наблюдаемых данных («стена»). Мы это измерили и задокументировали —
см. [WRITEUP.md](WRITEUP.md) (англ., для приза за лучшее объяснение решения).

партнёр при весе 0.35 (это и есть 7.096). Всё «умнее» — хуже.

## 📖 Подробно

### 1. Суть задачи
Предсказать `TVT` для eval-зоны (хвоста) горизонтального ствола. Дано: траектория
(`MD/X/Y/Z`), `GR` вдоль всего ствола, известная часть `TVT` у пятки, и эталонный
разрез `typewell` (`TVT` vs `GR` vs `Geology`). По сути — сопоставление GR-сигнатуры
горизонтали с эталоном (geosteering), а не табличная регрессия. Метрика — **pooled
RMSE** (пул по всем точкам, НЕ среднее по скважинам: per-well даёт обманчивые ~10).
Public = 26% теста, private = 74% (призы и медали решает private).

### 2. Валидационная методология (наш самый переиспользуемый вклад)
Public LB здесь **обманчив**: PF-кластер (форки ~7.2) определяется **дисперсией сидов**
— байт-идентичные перезапуски скачут 7.17–7.5. Тюнинг на Public LB = тюнинг шума.
Поэтому мы построили **честный локальный holdout**:
- 160 целых невиданных скважин (grouped split, seed 42), pooled RMSE на их eval-зонах.
- **Якорь достоверности:** flat на нашем holdout = 15.1 против LB 15.883 — шкала
  совпадает, значит ранжирование моделей на holdout можно доверять.
- **Правило (после болезненного урока):** сабмитить только то, что уверенно лучше на
  holdout И стабильно по фолдам/сидам. Public LB — не судья.

### 3. Что реально дало результат: декоррелированный PF-ансамбль
Публичный пайплайн = particle filter (128 сидов) + beam-search DP/Viterbi +
spatial FormationPlaneKNN/IDW + стэк LightGBM+CatBoost→Ridge + «gold» калибровка по
видимому префиксу. **Наши реальные добавления:**
1. Откат агрессивного GR-денойза (в изоляции +2.8%, на LB −0.24: 7.475→7.230).
2. **Diverse-config PF-ансамбль:** блендим базовый PF с *более жёсткой* конфигурацией
   (ниже process noise, `MOM/VN/PN = 0.999/0.001/0.002`) в весе 0.65/0.35. Две
   конфигурации делают *независимые* ошибки → усреднение снижает дисперсию.
   → **7.230 → 7.096** (ниже шумового порога 7.168 = реальный выигрыш).
3. **more-seeds версии** (128→160): вариансредукция, убирает фактор удачи → лучше
   переносится public→private (робастность для финалов).

### 4. Центральный вывод — «стена»
Почему flat так трудно побить? Потому что eval-зона `TVT` ведёт себя как
**near-random-walk вокруг последнего known-значения, направление дрейфа которого не
присутствует в наблюдаемых данных.** Подтверждено ~9 способами:

| # | Проверка | Результат |
|---|---|---|
| 1 | Flat baseline | 15.1 (сильный) |
| 2 | Экстраполяция линия/дип/поверхность | 37–85 (тренды не продолжаются) |
| 3 | Корр. дрейфа с ближайшим соседом | −0.08 |
| 4 | Бимодальный tie-break (±15ft Eagle Ford) | r=0.054, мода верна 48.8% (монетка) |
| 5 | Остаток PF vs любые наблюдаемые | \|corr\| < 0.15 |
| 6 | Изломы поверхности vs сдвиг GR | 0.082 |
| 7 | Изломы vs кривизна формаций | 0.293 (+формации убраны в тесте) |
| 8 | Oracle-регистрация GR-окон | ~31 ft (GR самоподобен) |
| 9 | Обученный контрастивный GR-матчер | **179 ft** локализации (без continuity GR не локализует) |

Вывод: эксплуатируемый сигнал = **continuity-приор** (держаться у последней позиции);
GR лишь слабо нудит локально; доминирующий дрейф (суб-сейсмические разломы) физически
не наблюдаем. 7.096 PF берёт почти целиком за счёт continuity + тонко настроенного
(намеренно *слабого*) GR-likelihood + стека beam/GBM/калибровки.

### 5. Может ли нейросеть побить настроенный PF? (7 архитектур)
Лидеры (~5.6) — предположительно регуляризованные CNN с хорошей генерализацией на
локальном holdout. Мы построили полный research-стенд (кэш 773 скважин, whole-well
holdout, аугментация) — и **каждая** архитектура с нуля проваливает flat (см. таблицу
в разделе «Все эксперименты»). Кульминация — **дифференцируемый grid Bayesian filter
(нейро-PF)** на GPU: правильная мульти-гипотезная архитектура, реально трекает позицию,
но сходится к flat **сверху (24.5)** — обученная GR-эмиссия **net-вредна** (чистая
диффузия без GR дала бы ≈flat=15, что лучше). Прямое доказательство: на этих данных
обученный GR-матчинг *вычитает* ценность. Полный план — [NN_RESEARCH_PLAN.md](NN_RESEARCH_PLAN.md).

### 6. Уроки
1. **Изолированные тесты компонентов врут.** Денойз, GBM-бленды, 4-way — все выглядели
   хорошо в изоляции и проиграли на LB. Переносился только full-pipeline / whole-well.
2. **Public LB ≈ шум сидов** для PF-кластера. Любое изменение < ~0.07 = шум.
3. **Знаем ГДЕ ошибка, но не КУДА править.** Магнитуду ошибки предсказать можно
   (seed-spread corr +0.48), знак — нет. В этом вся суть задачи.
4. **Вариансредукция бьёт «умные» идеи.** Единственный робастный выигрыш — декорреляция
   оценщика, не новая физика/фичи.

### 7. Финальные сабмиты
Выбраны **7.096 (diverse-PF)** + робастная **база 7.220** — перформанс-пик плюс
максимально-другая страховка. Соревнование на 74% private и *спроектировано* наказывать
переобучение под Public LB, так что дисциплинированная пара должна удержаться (или
подняться) на private, пока переоптимизированные решения просядут.
